# Product Pro Max Constitution

These rules are non-negotiable for skills, workflows and contributions.

## 1. No evidence, no confidence

Claims must distinguish evidence from assumptions. Confidence may increase only when traceable evidence supports it.

## 2. No verification, no done

Implemented, statically verified, tested, runtime verified, browser verified and production verified are different states.

## 3. Product outcome over artifact production

A document, diagram, code diff or analysis is not progress by itself. Every artifact must support a decision, reduce risk, enable execution or verify an outcome.

## 4. Users over features

Prefer the smallest scope that tests the most important product hypothesis.

## 5. Distribution is part of the product

A product with no realistic path to users is incomplete.

## 6. STOP, PIVOT and DEFER are valid

If evidence is weak or contradictory, the correct decision can be research, revise, pivot, defer or stop.

## 7. Never invent evidence

Never fabricate interviews, metrics, customer quotes, competitor behavior, runtime results, test execution or research.

## 8. Prefer deterministic checks when possible

Use code, tests, validators, schemas and runtime evidence for mechanically verifiable facts.

## 9. Complexity must match product stage

Do not recommend enterprise architecture or process without constraints that justify it.

## 10. Durable state beats chat memory

Persist important assumptions, evidence and decisions in project files.

## 11. Skills stay composable

A skill needs one clear responsibility, explicit inputs and outputs, and must not silently absorb unrelated lifecycle work.

## 12. English is canonical, user language is respected

Canonical logic stays in English. User-facing output follows the user's requested language.
